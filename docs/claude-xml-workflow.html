How Claude transformed a Paligo XML documentation workflow

How a persistent Claude prompt turned Paligo DocBook XML cleanup into a fast, consistent review-and-paste workflow.

By Prithviraj Lahare2026

On this page

    Originally written for a documentation team's internal knowledge base. Company and product names and system identifiers have been removed.

    Overview

    This case study explains how Claude was used to clean up a SaaS product's documentation set in Paligo. Instead of applying the same XML and style corrections topic by topic, Claude applied one persistent ruleset to every topic in the session, turning repetitive cleanup into a fast review-and-paste process.

    The problem

    The documentation set is stored in Paligo as DocBook XML. It had been migrated from an earlier system and arrived with legacy markup, inconsistent formatting, and structural issues. That meant hundreds of topics across user guides, how-tos, reference pages, and release notes, most needing the same family of fixes, each still needing care because malformed XML can quietly break publishing.

    • Time-consuming: roughly 15–30 minutes per topic by hand
    • Inconsistent: rules missed or applied differently between topics
    • Low-value: repetitive transforms with little creative or strategic value
    • Risky: malformed XML introduces hard-to-detect problems

    Standards applied

    AuthorityKey rules
    Google developer documentation style guidePresent tense, contractions, active voice, sentence-case headings, serial commas, "click" not "click on"
    Company voice and toneSecond person, no "please" in instructions, plain English for global readers, American spelling
    Paligo / DocBook conventionsCorrect elements, namespace formatting, valid admonitions, Paligo-compatible tables and images

    The prompt strategy

    Instead of one-off instructions per topic, I wrote a persistent project prompt that acted as a standing transformation specification:

    • Structural transforms: <literal> → <code>; <orderedlist> → <procedure>/<step>; legacy !!! note markers → DocBook admonitions; image placeholders → <mediaobject>; glossary placeholders flagged for a later pass; namespaces normalized.
    • Style rules: sentence-case headings, present tense, contractions, no "please," "click" not "click on," active voice, plain English.
    • Table rules: informaltable at 100% width with no colgroup; inline icons as <inlinemediaobject> inside <para>; UUID-based image references where required.
    Why it mattered: A persistent prompt turned Claude into a repeatable production tool rather than a one-off editing assistant.

    Execution: separate passes

    PassWhat it covered
    1. Structural cleanupElement transforms, admonitions, image placeholders, namespace formatting
    2. Cross-referencesInternal Paligo links (urn:resource:component:), external links, path-based links
    3. GlossaryDeferred replacement of glossary placeholders once the publication existed
    Parallel: SVG fixBulk repair of icons missing the xmlns attribute, re-uploaded with Paligo Replace

    I pasted raw XML into Claude, which returned transformed XML ready to paste back, plus a short summary of the changes so review could focus on what changed. Claude handled the mechanical layer; I stayed focused on technical correctness and publication intent.

    SVG icon repair

    Eight dashboard icons failed to render because the root svg element lacked xmlns. A bulk find-and-replace fixed the files, and Paligo's Replace function re-uploaded them so every existing reference stayed intact.

    Search:  <svg
Replace: <svg xmlns="http://www.w3.org/2000/svg"

    Key insight: The biggest benefit wasn't only speed. It was repeatable consistency, regardless of complexity, fatigue, or time of day.

    What Claude doesn't replace

    • Judging whether content is technically and architecturally correct
    • Choosing a new cross-reference target when the right one is unknown
    • SME and technical accuracy review
    • Content strategy: scope, information architecture, reorganization

    Claude was a force multiplier: it removed the mechanical burden so writing expertise stayed on quality, structure, and product knowledge.

    Recommendations

    • Use Claude for XML cleanup and transformation passes on new or migrated content.
    • Keep a shared prompt library so every writer applies the same rules.
    • Try Claude first for SVG and media troubleshooting before opening support tickets.
    • Keep cross-references and glossary work in separate passes.
