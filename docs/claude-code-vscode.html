Using Claude Code in VS Code for a documentation migration

Setting up and using Claude Code in VS Code to run a documentation migration.

By Prithviraj Lahare2026

On this page

    Originally written for a documentation team's internal knowledge base. Company names and system identifiers have been removed.

    This guide explains how to set up Claude Code in VS Code and use it to run migration scripts, review results, and troubleshoot issues. It covers only the editor and Claude Code workflow; the companion guide explains what the scripts do.

    Prerequisites

    • VS Code 1.98.0 or later. Check Help > About.
    • A Claude plan that includes Claude Code: Pro, Max, Team, Enterprise, or an Anthropic Console account billed at API rates. The free plan doesn't include Claude Code.
    • Windows: The standard installer needs no extra runtime. You need Node.js only for the npm-based install.

    Setup

    Step 1: Install Claude Code

    OptionWhen to use itHow
    VS Code extensionRecommended for this workflowIn Extensions, search for Claude Code, install it, and open the panel from the Claude icon in the sidebar.
    Command-line installerIf you prefer the terminalRun the installer in PowerShell, then verify the version.
     
    irm https://claude.ai/install.ps1 | iex
claude --version

    If you see "command not found," close and reopen the terminal: a terminal opened before installation doesn't see the updated PATH.

    Step 2: Authenticate

    The first time you open the Claude panel or run claude, your browser opens and asks you to sign in. Usage counts against your plan's limits, shared with the Claude chat interface.

    Step 3: Open your project folder

    Select File > Open Folder and choose your working folder. Claude Code can read and edit only files inside that folder, so keep your scripts and source content there.

    Workflow

    Step 4: Start with context

    Claude Code doesn't know what you discussed in another chat or changed outside the session. Start by summarizing:

    • Your working folder path
    • What's already done (scraped pages, converted files, imported content)
    • Recently added or changed files and what they do
    • The next steps, in order
    • Standing rules, such as never hardcoding credentials
    Good practice: State constraints explicitly: use environment variables for credentials, don't touch unrelated files, and explain failures before retrying a large conversion run.

    Step 5: Approve actions

    Claude Code asks before writing files or running commands. You can approve once, allow similar edits for the session, or decline and redirect. Allowing edits for the session is efficient inside your own local folder; be more selective with external systems, imports, and credentials.

    Step 6: Review output and manifests

    Commands run in the integrated terminal, so you see the same output you'd see yourself. After each build step, check pages converted, pages failed, assets bundled, and warnings. If the numbers look wrong, ask Claude Code to explain the discrepancy before moving on.

    Step 7: Hand off between chat and the editor

    1. Use Claude chat to think through an approach or debug a tricky issue.
    2. Get back a working or revised file.
    3. Paste a summary into Claude Code so it runs the solution against your real local files.

    Always restate the current state when you hand off: Claude Code can't see a separate chat conversation.

    A typical migration session

    1. Confirm prerequisites: Python, required packages, and source content.
    2. Ask Claude Code to run the conversion and report the manifest.
    3. Review the manifest together; investigate any failure before re-running.
    4. Decide whether Paligo cleanup is needed, such as deleting a previous test import.
    5. Do the Paligo import in the browser yourself. Claude Code can guide you from your description or screenshots.
    6. Spot-check a table, a procedure, an admonition, and an inline image.

    Troubleshooting

    IssueWhat to checkAction
    Claude Code can't see a new fileThe file may be outside the open folder, or in a similarly named oneMove it into the correct folder. A one-character difference in a folder name is enough to cause this.
    A command works in one terminal but not anotherEnvironment variables or new tools aren't loadedReopen the terminal panel or restart VS Code.
    You want approval prompts back"Allow all" lasts only for the sessionStart a new conversation.
