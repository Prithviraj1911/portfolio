Featured research · 2026

AI-assisted structured documentation: Paligo + Claude

Hands-on research into where an AI assistant genuinely speeds up work in a DocBook XML component content management system (CCMS), and where a technical writer still has to decide. Each study pairs measured results with the workflow and prompts that produced them.

Study 1 · XML transformation

A persistent prompt as a transformation spec

Encoded the style guide, voice rules, and DocBook conventions into one reusable prompt, then ran migrated topics through it in focused passes.

50+
topics transformed
15–30 → 2–5
minutes per topic
8
publication-blocking SVG icons fixed

Finding: The real gain is consistency. Every topic gets the same rules, regardless of fatigue or time of day.

Study 2 · Link triage

Separating real broken links from false positives

Used Claude to classify a CCMS debug report and trace flagged links through nested includes to their real source topic.

222
links classified in one pass
3–4 h → 10 min
categorization time
4 levels
of nested includes traced

Finding: Most flagged links were publication-scope false positives. Triage first, then repair, avoids edits that were never needed.

Study 3 · Content migration

Migrating legacy Markdown sites into Paligo

Built a scrape → navigation parse → DocBook package pipeline with Claude Code in VS Code, then applied it to a large legacy catalog.

150
pages in the validation migration
470
source files inventoried for the next catalog
533
images carried over; 182 orphans excluded

Finding: A source inventory before conversion surfaced the real risks: 296 unvalidated absolute links and a third-party image macro behind 92% of image references.

What this research shows

  • AI handles the mechanical layer. Element transforms, style normalization, and link classification are fast and repeatable.
  • Writers keep the judgment calls. Technical accuracy, information architecture, and choosing a correct cross-reference target stay with the writer and SMEs.
  • Structure makes AI useful. Raw XML source, explicit rules, and separate passes give far better output than general descriptions.

Earlier projects & findings

Projects I led or contributed to inside organizations. Product names, client names, and internal data are generalized; metrics are my own reported results.

Docs-as-code · Healthcare Moving 5+ medical products to modular, version-controlled docs −40% manual editing

Context

Documentation for several healthcare products lived in separate tools with manual copy-paste between versions. Reviews were inconsistent, and compliance wording drifted between products.

What I did

Evaluated platforms, then rolled out Mintlify with a shared component library, Git-based review, and a common review checklist covering MSTP and HIPAA language.

Outcome

Manual editing effort fell by 40%, and delivery efficiency across the product set rose by 25%.

Finding

Reuse pays off only when the review process changes too. A shared checklist did as much for consistency as the new tooling.

AI & chatbots Structuring documentation so a chatbot can answer from it Docs as AI source of truth

Context

A product chatbot gave answers that conflicted with the published docs because it drew on a separate, hand-maintained knowledge base.

What I did

Designed JSON schemas for AI ingestion, synced content with live product data, and built a prompt library and structured datasets with developers.

Outcome

The chatbot and the docs drew on one source, giving more consistent, context-aware answers and better user engagement.

Finding

Writing for AI retrieval favors short, self-contained topics with explicit metadata: the same habits structured authoring has always rewarded.

DITA XML · Banking & automotive Introducing content reuse in regulated documentation −30% duplication · −35% maintenance

Context

Core banking modules and automotive manuals repeated the same procedures and warnings across many documents, so every change had to be made several times.

What I did

Audited content for reusable units, defined a DITA topic and map strategy with conrefs and keys, and coached teams on modular authoring in Oxygen XML and FrameMaker.

Outcome

Content duplication fell by 30% (banking) and maintenance effort by 35% (automotive).

Finding

Starting with the most-repeated 20% of content (safety notes, prerequisites) delivered most of the gain and built team buy-in.

Migration Migrating 100+ legacy Word documents to XML templates +50% update efficiency

Context

Deployment and end-user guides were maintained as standalone Word files with inconsistent formatting across five global teams.

What I did

Built standardized XML templates, migrated and cleaned 100+ documents, and aligned the workflow with Agile sprint cadence.

Outcome

Updates became 50% faster, and all five teams shared one template set.
